# Research and design rationale

November 4, 2026. Primary product documentation, accessibility guidance and original research inform this proposal. These are transferable patterns, not comparative usability scores or evidence that a reference product works for everybody. Recommendations for World Explorer are design hypotheses until tested with its players.

| R02 | [Forza: Horizon Adventure](https://forza.net/news/forza-horizon-5-road-to-mexico-september-update) connects player-chosen branches with smaller challenges and longer goals. | Show a completed piece of work, its actual benefit and a selectable next assignment. | R06 | [iNaturalist: observation workflow](https://help.inaturalist.org/en/support/solutions/articles/151000192921-how-to-make-an-observation) separates evidence, encounter details, saving and sharing. | Research reports should expose original evidence, provenance and limits; save and upload need distinguishable status. | World Explorer's modeled training observations are not verified real-world scientific records. |
| R07 | [NN/g: progressive disclosure](https://www.nngroup.com/articles/progressive-disclosure/) defers specialist details until requested. | Prioritize a useful start and current task; keep all careers, instruments, layers and controls reachable through stable categories and search. | Hiding essential controls or putting a frequent action several levels down defeats the purpose. Essential safety/save information is never an advanced option. |
| R08 | [NN/g: recognition and recall](https://www.nngroup.com/articles/recognition-and-recall/) explains the value of recognizable choices and context. | Use labeled world choices, readable place breadcrumbs, recent work and current input prompts. | Icons and keyboard shortcuts supplement visible labels; players should not need to memorize where Journal moved between worlds. |
| R09 | [Xbox guideline 101: text](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/101) treats HUD, instructions and settings as important readable text. | Set a common type scale, opaque panel surfaces, full-content scaling and a persistent larger-text choice. Test the actual rendered glyphs and viewing distance. | CSS font size alone does not establish game/VR text readability. | R10 | [Xbox guideline 107: input](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/107) covers alternatives to analog input, prolonged holds and rapid sequences as well as remapping. | Keep existing action bindings; plan optional toggle/hold alternatives, non-drag editing and discoverable mode-specific controls. | Any assist that changes competitive performance must retain existing class/rule identity. A UI preference cannot silently alter ranked physics. |
| R11 | [Xbox guideline 112: UI navigation](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/112) emphasizes predictable structure, interaction and focus. | Use the same primary destinations in selector, Earth, Ocean and Space, with a common return model and contextual specialist controls. | Consistency means the same meaning and command, not identical pixel placement in VR and on a phone. |
| R12 | [WCAG 2.2 target size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) defines a 24-CSS-pixel minimum with specified exceptions; [new WCAG 2.2 criteria](https://www.w3.org/WAI/standards-guidelines/wcag/new-in-22/) also address obscured focus and dragging alternatives. | Adopt a stronger 44×44 CSS-pixel product target for primary touch controls, with spacing; prevent sticky UI covering focus, and give track/build editing click or keyboard alternatives. | A measured 34px control misses the proposed product target; that alone does not prove a WCAG failure. | R13 | [WAI-ARIA dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) defines contained focus, initial focus, Escape and return focus. | Apply existing modal/layout ownership consistently. | R14 | [W3C XR Accessibility User Requirements](https://www.w3.org/TR/xaur/) describes multimodal input, customization and motion-independent needs. | Provide seated/reachable navigation, ray/controller equivalents, recentering, motion comfort settings and readable spatial panels using the existing XR/platform adapters. | This is an informative requirements note, not a baseline conformance standard. | R15 | [Ryan, Rigby and Przybylski, 2006](https://selfdeterminationtheory.org/SDT/documents/2006_RyanRigbyPrzybylski_MandE.pdf) relates autonomy, competence, intuitive controls and relatedness to enjoyment and future play, with stated study limitations. | Make return visits worthwhile through visible mastery, player choice, useful unfinished work and optional collaboration. | This does not establish a causal retention gain for World Explorer, predict D1/D7 rates or justify manipulating attendance. Measure actual outcomes and player understanding. |

## Method applied

Inventory the shipped feature families and their owners first. Trace choose → prepare → act → result → save → resume, along with cancel, denial and failure. Inspect current screens at representative sizes; distinguish current live observations from source-only and retained acceptance evidence. Compare complete task flows and information architecture, rather than scoring visual resemblance to another game.

The resulting three options vary what comes first: a place, a next journey, or a specialist workspace. All retain the selected Roam identity and the same feature-preservation contract. The recommended direction must still be evaluated through tree tests and uncoached task attempts. No player interviews, retention experiment, screen-reader audit or physical-device study was conducted during this research pass.
