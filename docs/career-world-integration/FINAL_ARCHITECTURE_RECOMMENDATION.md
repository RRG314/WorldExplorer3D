## Why this fits the app

World Explorer already has character practice, twenty career entry paths, meaningful scientific/racing/creative outcomes, a Journal and rich travel systems. The first-player audit reached a genuine saved result and badge. The missing piece is a coherent handoff and visibility hierarchy, not another account/profile/inventory/progression framework. EVE’s tracked-goal mechanism and other official references support the design analogy, but its suitability here is a source-backed engineering judgment; retention gains are not established.

Keep one original identity and all permanent progress. Make a focus an optional preference that ranks valid opportunities. Keep accepted task, character background, qualifications and travel mode separate. An active task/recovery owns guidance ahead of a focus. All meaningful work can still award appropriate existing practice while another interest is tracked. Changing focus never resets a character, grants tools, starts a mission, cancels a trip or moves a room.

## Concrete design

The globe remains. Explore selects where; Activities starts real work; Journal keeps evidence/story/skills; Create and Together retain their original owners. Initially keep those five destinations and improve hierarchy rather than remapping every route. Present one Continue/current objective with deliberate alternatives. Show useful owned/provided tools first; stores only for real missing requirements. Keep the world/control space clear, quiet help available, accessibility settings findable and real device bindings correct.

New players may choose an interest early (A), take the short universal foundation (recommended B), or explore immediately (C). Returning players bypass creation/grants and can continue actual saved work. A career-specific introduction teaches its next real operation and completes from existing domain evidence. Avoid twenty new XP ladders or an empty qualification framework. Advanced readiness can become optional depth when a real curriculum and unlock exist.

Geology uses cited map context; occurrences, historical mines, assessments and game resources remain distinct. The current game endpoint’s metadata is still conterminous coverage; a v2 announcement is not an endpoint migration. Existing authored Geology and fictional quarry work stay intact. Add a source only after product/version/rights/coverage/schema/outage validation, never by converting a map response into ore or extraction permission.

Multiplayer first preserves mixed personal focuses in existing shared contexts. New joint research objectives and contribution payouts need a separately scoped server domain extension. Do not imply every personal course is already cooperative. Shared room authority and personal evidence remain separate.

## Proposed engineering boundary

Add optional versioned focus metadata inside the existing profile and a small event-driven projection beside existing current-journey logic. Use original versioned experience entry, latest-profile functional updater, capability snapshots, one active plugin, lifecycle/Abort guards, provider caches, Backpack/economy/room authorities. No new per-frame scan, second render loop or whole-Journal polling. Gradually extract demonstrated duplicated view logic; do not rewrite the app’s world/runtime spine.

Existing character/Backpack/Journal/media/housing/vehicle migrations remain. Shared-device Journal is not full account cloud sync. Unknown future data, failed saves, pending receipts and rollback bytes stay recoverable. Full cloud Journal sync, new industrial careers, a global MMO and credential economy are not smuggled into this integration estimate.
