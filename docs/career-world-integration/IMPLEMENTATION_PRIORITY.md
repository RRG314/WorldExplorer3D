# Finite implementation packages

**Owner decision is the next product gate.** R&D does not authorize selecting the architecture automatically. Recommendation C + onboarding B, with A/C available, is described in the final recommendation. The local hint visibility repair is independent and does not migrate the app.

Estimates are focused engineering/verification days for one contributor using existing accepted systems, not promises of wall-clock delivery. Hardware-constrained sequential world checks and owner/human/device availability affect elapsed time. New industrial content, full Journal cloud sync or a global MMO is excluded and needs a new estimate.

| --- | --- | --- | --- |

Core recommendation: roughly **13–26 focused engineering days**, with uncertainty reduced after P1/P2. This is a scoped integration estimate, not the original full app built anew. If only a narrower initial release is desired, owner must explicitly select its deferred features; do not call the complete requested architecture finished by quietly dropping P3/P4/P5.

## Optional extensions kept out of the core estimate

New server cooperative research task/contribution settlement: 5–10 additional days for one narrowly specified task, then actual two-client acceptance. New playable aviation, Wilderness or processing/refining careers: content-dependent estimate after a concrete vertical slice is defined. Qualification curriculum beyond existing checks: approve evidence/unlocks/content first. Account-isolated full Journal cloud sync: separate identity/privacy/storage migration project. No placeholder cards or invented grants substitute for any extension.

## Stop rules preventing another endless loop

Each package has one ledger and named failing boundary. Once its acceptance passes, close it; do not replay unchanged full careers/laps. New failures re-open only their affected owner/boundary. Preserve failed attempts and diagnose before another heavy run. A test-count increase is not a product milestone. Unknown/blocked scope is shown explicitly, with a decision or bounded next action. At P6 deliver the exact candidate and open issues; no automatic production deployment.
