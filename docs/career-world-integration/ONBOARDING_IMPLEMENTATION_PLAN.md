## Implementation choices

Extend existing `current-journey` projection and tutorial state, preserve versioned experience intents and adapter offers, profile functional updater and original event handlers. Use shared design tokens/controls and forwarded action IDs. No per-frame career scan, new provider cache, new wallet or second active plugin. Default control hints come from actual bindings; accessibility settings and input mode remain original authorities.

## Test strategy

Pure projection tests for priority/availability; original controller integration for consent/meaningful-event/exact-review transitions; actual IndexedDB/legacy/export tests only for changed state fields; browser layout checks for changed surfaces; ordinary clean-profile result journey once per affected device class. Diagnose and retain failure before rerun. Existing science/lap/marine/space procedures remain closed except a demonstrated changed dependency.

Account creation, shared-device Journal scope and native hardware need their own explicit evidence classes. The successful desktop staging first result does not close unrun clean-phone completion or post-reload Journal visuals. A headless UI pass does not close assistive-device or mixed-age comprehension research.

Deliver each O step with source diff, exact evidence, limitations and next hard stop. No new scope is silently added while fixing presentation. Product completion is real play/result/resume and coherent control flow, not the number of tips or test files.
