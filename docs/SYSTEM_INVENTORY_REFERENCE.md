## Street replacement on the R&D branch

The active carriageway compiler is [street-carriageway.js](../app/js/world/compiler/street-carriageway.js), with [street-carriageway-mesh.js](../app/js/world/compiler/street-carriageway-mesh.js) producing unioned road surfaces. [street-pavement.js](../app/js/world/compiler/street-pavement.js) uses the same road boundaries, [street-frontage-geometry.js](../app/js/world/compiler/street-frontage-geometry.js) resolves visible facades, and [street-frontage-corners.js](../app/js/world/compiler/street-frontage-corners.js) constructs corners from supported facades and curbs.

RDT identity and exact spatial capture lookup are restored (see `audits/2026-09-16-rdt-restoration/README.md`). Geographic-hash content thinning remains disabled. Per-road ground sheets, the circular junction-cap generator and tile-local pavement closing filter remain retired. The remaining `road-surface-geometry.js` provides turn footprints and the pavement conformance helper; it no longer provides an alternate ground-road generator.

This replacement is not release accepted. The [implementation evidence](streets/STREET_REPLACEMENT_IMPLEMENTATION_STATUS.md) records unresolved regional boundary, grade-authority, loading and memory gates. The [approved replacement plan](streets/STREET_SYSTEM_REPLACEMENT_PLAN_2026-09-14.md) remains the scope of the work.
