# State and evidence authority

This contract describes the current implementation. “Saved by the server” does not mean the server independently simulated or verified the original action. The architectural polish keeps the sandbox and does not introduce an authoritative competitive simulation.

| Field / decision | Owner and accepted input | Persistence / trust boundary |
| --- | --- | --- |
| Local actor pose, vehicle handling, camera, appearance | Current environment and transport/character controllers; accepted simulation clock | Browser sandbox simulation. Room pose replication is presentation, not proof of collision or travel legality |
| Environment, world request generation, pause | Session coordinator, world loader, pause owner | Latest-generation publication and owner cancellation; no unrelated feature may commit an old environment result |
| Signed-in UID, account claims, paid entitlements | Firebase Authentication and server entitlement authorities | Never inferred from local profile, device inventory, App Check alone, or a client-selected UID |
| Wallet balance, purchases, property ownership, rental/sale mutations | Transactional economy/property authorities and authoritative catalog | Server validates identity, revision, catalog, balance and mutation identity. Local wallet display is a projection |
| Shared marine seat/helm/pilot leases, accepted vessel/sub pose, manifest | `marine-expedition-authority.js`; room membership, server time, bounded motion, revision/idempotency | Client predicts under an acknowledged lease; reconciliation restores authoritative state after uncertainty. A lease is exclusive control, not world-scale ocean physics verification |
| Shared Expedition command state and permitted actions | Browser command authority plus reproducibly generated Functions engine | Server runs the shared rules in transactions. Matching generated bytes is now a dependency gate |
| Personal Journal items, observations, events, guide and authored local structures | Local profile store transactions; original data plus derived Journal indexes | Device-owned IndexedDB. Import/rollback retains unknown data; account switching does not relabel personal local history as another account's server receipts |
| Account condition / health | Client simulation reports condition; server validates schema/revision/idempotent mutation | Durable per-account intent survives retries/tabs. Server storage is authoritative for acknowledged revision, not independent damage/combat simulation |
| Flower, Paint Town, Fishing, DeFlock scores | Client gameplay reports; Firestore rules validate signed identity, shape and bounds | Casual player-reported results. These are not independently verified runs; do not attach competitive prizes to these claims |
| Community leaderboard activity | Account-owned activity/profile and bounded rules (`explorerLeaderboard`) | Community activity totals; client updates remain permitted under rules. Not an anti-cheat ranking |
| Property leaderboard portfolio totals | Server property transactions; direct client writes denied | Recorded virtual property activity. Does not prove real-world ownership, legal title or valuation |
| Real-world mapped footprints/roads/water/terrain | Source-specific world compiler, ground and transport authorities | Data provenance and source coverage remain distinct from visual decoration and playable simplification. A photorealistic asset cannot redefine geographic truth |
| Forecast, wave/current model, predicted tide, orbit propagation | Provider model/prediction at a dated point and validity time | Modeled/predicted; must not be called a local sensor measurement or universally current |
| NOAA station water level, aircraft observations, earthquake records | Dated provider observations with station/location qualification | Observed source data; provider latency and coverage remain visible. No data is not a zero value |
| Cameras / street imagery | Approved source image and capture timestamp when available | A still image is not live video. Unknown capture time is unknown; viewer/browser fetch time does not establish capture time |
| Fish, wildlife encounters, scuba capability, authored marine scene | Game ecology/capability rules and water simulation; labeled evidence where applicable | Virtual gameplay and authored habitat. Not a claim that a specimen or safe dive exists at those real coordinates |
| Capture uploads, reconstruction, placement | Capture ownership/storage rules and reviewed reconstruction/placement authority | User media is private according to existing access rules. Reconstruction appearance is not survey-grade geometry or authoritative property ownership |

The public gameplay boards are to be labeled as casual/player-reported in the existing UI; account portfolio totals retain their different authority. No score values, saved records, reward rules, leaderboard ordering or access rules need changing for that disclosure.

## Local save compatibility

Journal v5 adds derived metadata but preserves original records and export data. An old v4 opener cannot open the higher-version database. The generation-bound Backpack control supplement and account condition IndexedDB outbox also require compatible readers. A hosting rollback to a preserved old artifact is therefore not yet a migration-compatible rollback. Package 6 must verify a compatible fallback artifact or a tested compatibility path before release; never delete/downgrade player data to make an old frontend boot.
