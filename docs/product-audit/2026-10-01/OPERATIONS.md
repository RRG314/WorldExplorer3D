# P19 operations — engineering closeout and launch gates

October 3, 2026. This closes the finite runtime resilience/provider-intake work for the product-plan slices. It does not attest a paid account, a production deployment or every location worldwide. An existing paid Open-Meteo subscription has not been established; the owner has been asked. That remains a commercial-release gate, not a reason to leave the implemented journeys unfinished.

## Implemented and verified

- The shared geospatial registry limits active queries to eight, coalesces even forced duplicate refreshes, gives each consumer independent cancellation, aborts when its last consumer leaves, rejects already-cancelled work, and times out a provider even if it ignores AbortSignal. A removed provider cannot publish a late result. Failed requests have a bounded retry cooldown. Cache timestamps reflect acquisition, never the later retry; failures do not create false empty current data.
- Camera JSON, forecast/marine JSON and orbital text use decoded streaming byte limits. This bounds responses even when Content-Length is absent or refers to compressed bytes. Camera limit is 3 MB; weather/marine/earthquake JSON 5 MB; orbital text 3 MB per admitted group. Existing consumer-specific stale/fallback labels remain; no old marine sample is silently promoted to a new site's physical authority.
- Search and reverse lookup now go through `getPlaceLookup`, with App Check required on the production handler. A shared Firestore lease serializes upstream calls across all instances and both kinds of lookup. The next call starts only after the previous response plus 1.1 seconds. Failures impose ten seconds of backoff. At most 5,000 uncached upstream requests are admitted per UTC day; the budget is a conservative app limit, not a provider entitlement. Four Function instances and 20-second execution deadlines bound concurrency. Lookup cache expires after seven days; the TTL field and payload index exemption are declared in firestore.indexes.json. TTL deployment/activation is a release prerequisite, and asynchronous deletion is not an exact deletion-at-expiry guarantee.
- Search cache keys hash the normalized provider URL; raw queries/user IDs are not logged or stored as cache keys. Cached results are public geographic records, not user travel histories. Clients cannot read the server cache or edit its lease. Provider changes invalidate cache identity. `PLACE_LOOKUP_BASE_URL` accepts an operator-controlled HTTPS Nominatim-compatible base without credentials/query parameters; clients cannot choose an upstream URL. No automatic fallback leaks traffic to a second unmanaged geocoder. Coordinates and saved places remain usable when lookup is unavailable.
- Local previews use the same emulator authority through `WE3D_PLACE_LOOKUP_EMULATOR_ORIGIN=http://127.0.0.1:5001`. Without that emulator, lookup returns a readable unavailable response; it never bypasses the global limit with another direct public request. The actual preview search is tested. Source alone is not a deployed backend.
- Overture is pinned to reviewed `2026-09-23.1`. The old August release had only 14 days of the declared retention window left. The source gate now uses the actual date rather than a hard-coded August date, checks review chronology and requires 14 remaining retention days. Release notes and actual byte-range/tile reads were reviewed; this app does not consume the removed Places categories field. Existing dataset provenance remains explicit.
- Marine asset review verifies all six near/far GLB hashes and byte counts against the CC0 Smithsonian manifest: three shapes, 1,373,484 total bytes, each mesh below 10,000 triangles. These are authored regional habitat visuals, not evidence of a specimen's real location. Existing local asset rights manifests and credits remain retained with source/artifact inputs.

## Workload calculations, not a price quote

A four-still camera wall schedules at most 24 image loads per visible hour after initial load. Four Finland sites can add 48 detail metadata calls/hour; California uses two catalogue calls/hour. Actual mixed-wall test: 20 requests including induced failures and reload, 843,578 known image bytes, 6,570,971 known metadata bytes, three responses with unknown Content-Length. Browser caches/compression and image sizes vary. Hidden/closed views issue no scheduled refreshes.

A marine voyage with two controlling users has up to 2,880 scheduled authority requests per active hour, plus explicit player commands. Each successful mutation writes the shared document and fans out to its listeners. At twelve listeners that is up to 34,560 listener document deliveries/hour, before reconnects; the transaction also reads the room, expedition and current room-player collection. This is a workload estimate, not a fixed billing ceiling: transaction retries, stale player rows, presence, reconnects and interactive commands add work. The client cadence is not an adversarial rate limit. Use actual Firebase request/read/write/egress metrics before choosing a public concurrency promise; server-side abuse throttling across all existing APIs remains a release security review item.

Geocoder uncached work is capped at 5,000/day; a fully utilized seven-day cache can hold roughly 35,000 entries before asynchronous TTL lag. Cache hits still incur a Function invocation and database read. TTL deletions and transaction retries have costs. App Check, instance limits and the upstream budget reduce exposure but are not a billing hard stop; configure cloud budget alerts and review actual traffic before broader launch.
