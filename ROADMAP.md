# World Explorer 3D Roadmap

Last updated: 2026-08-30.

World Explorer 3D is growing toward a connected world sandbox: choose a real
place, build an Explorer, travel by land, water, air, or space, and make a
persistent life in the game. New systems must deepen that shared world instead
of adding another disconnected menu or duplicate version of an existing
feature.

## Product direction

The long-term game is organized around five connected parts:

1. **Explore:** go anywhere the available world data and game environments can
   support, from a city street to a regional field site, an ocean, or another
   world.
2. **Do:** drive, fly, sail, fish, survey, photograph, collect, trade, build,
   care for companions, play activities, and share a room with other players.
3. **Grow:** develop an Explorer identity, specialties, equipment, companions,
   vehicles, homes, and expedition capabilities.
4. **Belong:** establish homes and base camps, decorate them, return to familiar
   places, and contribute to persistent local or multiplayer worlds.
5. **Create:** use one World Editor and Blocks workflow to make structures,
   interiors, activities, and shared places without competing building systems.

Real-world context makes the sandbox recognizable, but it does not turn the
game into a navigation, appraisal, ownership, wildlife-presence, or safety
service. Unknown source data remains unknown.

## Next foundation: persistent player life

These systems come before a larger virtual property economy because they define
who owns progress and how it remains recoverable.

### Explorer identities and character growth

- Let players choose an Explorer style such as naturalist, field researcher,
  navigator, builder, pilot, mariner, photographer, or generalist.
- Keep one shared Character model. An Explorer style changes starting strengths,
  assistance, activities, and growth paths; it does not create separate movement,
  inventory, vehicle, or fieldwork systems.
- Add player-selectable avatars, appearance options, clothing, equipment display,
  animation quality, and accessibility choices.
- Connect attributes, skills, specialties, companion bonds, licenses, equipment,
  and vehicles to clear milestones and visible next steps.
- Avoid permanent early mistakes: players can keep a generalist path, learn
  outside their specialty, and revise their focus without losing their history.

### Account-backed progression

- Add recoverable account sync for the Character, Backpack, Journal, Guide,
  companions, homes, base camps, vehicles, and supported creations.
- Preserve local-first play and export/restore while making conflict resolution,
  migration, rollback, and account deletion understandable.
- Keep rewards and shared ownership server-authorized. A visible client state is
  never sufficient proof of ownership.
- Connect public competition to clear categories: fieldwork, games, making,
  travel, community, companions, and seasonal programs.

Completion means a player can sign in on another supported device, recover the
same supported progression, understand any conflict, and continue without a
duplicate profile.

## Homes, base camps, and virtual real estate

Property will become a progression system built on the existing mapped building,
interior, Editor, Blocks, room, and account systems. It will not be a second
building game.

### Stage 1: homes and base camps

- Let a player choose one primary home and establish a limited number of base
  camps for longer expeditions.
- A home provides storage, companion rest, a vehicle return point, decoration,
  activity planning, and a recognizable place to return to.
- A base camp supports field equipment, route planning, sample review, companion
  care, and expedition recovery without pretending the player owns real land.
- Home and camp placement must respect mapped access, protected places,
  sensitive-species rules, room permissions, world bounds, and collision.
- Decoration uses the World Editor and Blocks object authority, with furniture,
  materials, placement limits, undo, persistence, and room sharing.
- Interiors retain stable floor and building identity so saved decoration does
  not move to another structure after a later world load.

Completion means a home or camp can be entered, decorated, saved, revisited,
shared when permitted, migrated, and recovered after an interrupted session.

### Stage 2: virtual property market

- Create virtual property records from stable mapped building identity and
  licensed property data where coverage permits. A game property is never a
  claim to legal title, access, tenancy, or control of the real property.
- Support buying, selling, and upgrading with game currency only. The first
  release will not include cash-out, real-money speculation, mortgages, or a
  promise that virtual holdings retain value.
- Use a licensed valuation source only when the provider permits the intended
  display and storage. Show the source date, coverage, confidence or range, and
  whether a number is an assessment, listing price, sale record, automated
  estimate, or game value.
- Never substitute random prices for fair market value. If usable valuation data
  is missing, show that it is unavailable and use a clearly named game-price
  model that does not claim to represent the real market.
- Keep private owner, mortgage, and other personal records out of ordinary game
  play. Property identity and valuation are separate from personal ownership
  information.
- Start with regions where licensing, parcel identity, valuation coverage, and
  update policy can be verified. Elsewhere, homes and base camps can still use
  the game economy without a fair-market-value claim.
- Add economic sinks and safeguards through maintenance, decoration, travel,
  storage, services, and bounded resale rules so progression is rewarding and
  resistant to inflation or abuse.

Completion means every displayed value has an understandable source and date,
every transaction is authorized and recoverable, and no game screen can be
mistaken for a real listing, appraisal, deed, or offer.

### Stage 3: neighborhoods and shared places

- Let invited players visit homes, contribute within explicit permissions, and
  use shared storage or activities without gaining ownership authority.
- Add clubs, settlements, expedition headquarters, marinas, hangars, workshops,
  farms, and research stations as extensions of rooms and homes.
- Connect local businesses and services to travel, repairs, equipment, supplies,
  companion care, and trade while retaining exact source and place identity.
- Add community showcases and discovery without making private locations or
  sensitive real-world details public by default.

## World depth and realism

World depth will expand by strengthening shared simulation owners rather than
adding city-specific exceptions.

### Earth and built environments

- Improve reviewed roads, bridges, tunnels, rail, ports, airports, shorelines,
  terrain, roofs, entrances, interiors, elevators, lighting, and collision.
- Expand building materials, architectural families, usable rooms, rooftop
  access, furnishings, weather response, and day/night activity.
- Add more playable vehicles and vessels through shared catalogs, handling,
  damage, repair, entry, storage, and facility rules.
- Keep the personal mode-switch vehicles distinct from heavier world vehicles.
- Extend city-switch and memory cleanup so repeated travel remains playable on
  supported desktop and mobile hardware.
- Give projectiles, spent charges, dropped items, downed actors, wrecks, and
  unmanned vehicles bounded lifetimes or recovery rules. Cleanup must dispose
  rendering and physics resources, not merely hide them.

### Natural world and field play

- Publish more reviewed ecology packs through the same taxonomy, habitat,
  seasonality, provenance, licensing, attribution, localization, migration,
  rollback, and sensitive-species requirements.
- Improve creature anatomy, scale, behavior, animation, LOD, sound, tracks,
  habitat signs, and mobile budgets by quality tier.
- Expand regional geology, weather, water, insects, fish, marine life, farms,
  livestock, and seasonal change without claiming generated play is a live
  observation.
- Develop companion training and roles that connect to fieldwork, travel, homes,
  and specialties without turning wildlife encounters into real-world capture
  claims.

### Ocean and space

- Expand marinas, harbors, large ports, ships, navigation, research, rescue,
  cargo, fishing, diving, and oceanography through one maritime lifecycle.
- Expand planetary and deep-space destinations with body-appropriate surfaces,
  atmospheres, hazards, activities, visuals, and return journeys.
- Preserve manual control. Assistance remains optional, visible, local to the
  selected destination, and interruptible by the player.

## Creation and community

- Extend the World Editor with terrain-safe voxel and material tools while
  retaining Blocks as its immediate persistent construction workflow.
- Add reusable interiors, decoration sets, vehicles, activities, routes, and
  field programs through reviewed catalogs and clear rights metadata.
- Improve drafts, validation, version history, moderation, rollback, discovery,
  attribution, and creator profiles.
- Add cooperative Expeditions, races, surveys, building projects, port and
  airport activities, seasonal events, and community challenges.
- Carry transport, equipment, damage, recovery, and cleanup into multiplayer
  through the existing room authority. The room service decides shared entity
  state and retirement so one client cannot erase or retain objects for
  everyone else.
- Add an in-game multiplayer map showing the current online player count,
  discoverable rooms, and privacy-safe approximate activity areas. Precise
  player coordinates remain visible only inside a room when its permissions
  allow them, and players can opt out of public discovery.

### Combat and action feel

- Improve sight alignment, camera-to-muzzle agreement, hit feedback, recoil,
  spread, projectile speed, throwing arcs, animation, sound, and mobile aiming.
- Keep one equipment and projectile authority across the Backpack, quick slots,
  NPC response, damage, pickups, rooms, and cleanup.
- Treat the current ranged-action system as a playable foundation, not the
  final standard for precision shooting or finished weapon presentation.

Completion means a creation has one owner, one persistence path, clear
permissions, a recoverable history, and predictable behavior in solo and room
play.

## Ongoing release standards

Every release must:

- preserve supported player state and provide migration and rollback where the
  schema changes;
- test the changed gameplay path in the browser on the exact release build;
- retain usable keyboard and 390×844 touch entry, action, exit, and recovery;
- distinguish mapped, observed, modeled, reference, and game-created content;
- document data source, license, attribution, age, coverage, and uncertainty;
- avoid duplicate movement, inventory, building, progression, property, or
  multiplayer authorities;
- compare public notes with the previous production tag so substantial player
  changes are not omitted;
- publish only the build that completed owner review.

Worldwide completeness will not be claimed from a set of regional packs,
provider fallbacks, or generated visuals. The roadmap advances when each new
capability works as part of the game players already have.
