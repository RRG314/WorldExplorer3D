WORLD EXPLORER 3D — OPEN-ENDED EMBODIED AGENT SOCIETY EXPERIMENT
FULL SNOW-GLOBE / ARTIFICIAL SOCIETY RESEARCH PLATFORM

Work from the isolated World Explorer embodied-agent experiment branch/staging
environment created for the autonomous maintainer experiment.

DO NOT modify or deploy production.

DO NOT build this as NPC gameplay for human players.

This is a research environment.

The long-term objective is to place persistent autonomous AI agents inside
World Explorer and observe what happens when they must live within the same
world, satisfy needs, interact with one another, learn independently, communicate,
use resources, solve problems, and—only when justified—repair or extend the
software environment they inhabit.

IMPORTANT:

DO NOT hardcode the desired society.

Do not assign:

farmer
hunter
merchant
programmer
leader
mayor
government
economy
religion
police
families
social classes
laws
currency
political systems
institutions

unless one of those is explicitly required as an experimental control.

If agents independently converge on behaviors resembling these structures,
record that as an observation.

The experiment asks what happens.

It does not attempt to make a predetermined civilization appear.

============================================================
1. CENTRAL RESEARCH QUESTION
============================================================

Build an experimental platform capable of investigating:

How do populations of persistent embodied AI agents behave when required to
satisfy long-term needs in a shared interactive environment while possessing
individual memory, incomplete information, communication, physical capabilities,
resources and consequences?

Secondary questions include:

Do persistent social relationships emerge?

Does cooperation emerge?

Does specialization emerge?

Does exchange emerge?

Does resource inequality emerge?

Do agents create shared conventions?

Do agents create persistent shared artifacts?

Does collective problem solving emerge?

How does information propagate?

How does false or incomplete information propagate?

Do agents establish stable homes?

Do agents develop recurring behavioral roles without roles being assigned?

Do agents coordinate resource acquisition?

Do agents migrate when local conditions become difficult?

Do groups form?

Do persistent institutions emerge?

Can agents collectively identify environmental/software failures?

Can they distinguish:

normal world difficulty,
missing source data,
software defect,
and missing capability?

Can agents repair genuine software defects they discover through ordinary life?

Can agents propose and construct missing capabilities when persistent goals
cannot otherwise be satisfied?

Do different populations develop differently from the same initial conditions?

Do different real geographic environments produce different behavior?

============================================================
2. SCIENTIFIC INTEGRITY
============================================================

This experiment must make it impossible to confuse scripted behavior with
emergent behavior.

Maintain explicit classifications:

DESIGNED CONSTRAINT

Example:
agents require water.

DESIGNED AFFORDANCE

Example:
agents can communicate.

EXPERIMENTAL TREATMENT

Example:
one population has shared written records.

AGENT-INITIATED BEHAVIOR

Example:
agents repeatedly exchange food.

EMERGENT PATTERN

Example:
one agent becomes the dominant resource supplier despite no assigned occupation.

Do not label something "emergent" merely because an LLM generated it.

The behavior must arise from interactions under the experimental conditions
without the specific outcome being instructed.

Each has its own:

============================================================
5. BELIEF ≠ TRUTH
============================================================

This is essential.

Maintain separate:

WORLD TRUTH

what the experimental evaluator knows.

AGENT OBSERVATION

what the agent perceived.

AGENT BELIEF

what the agent currently thinks.

COMMUNICATED CLAIM

what another agent told it.

SHARED RECORD

what has been stored externally.

Agents must be capable of:

being uncertain
being mistaken
holding stale information
receiving conflicting information
correcting beliefs.

Do not automatically synchronize beliefs with world truth.

============================================================
6. BASIC NEEDS
============================================================

Start with a small universal need set:

water
food
rest/shelter
health.

Needs should:

change over simulated time
have consequences
be satisfiable through multiple legitimate strategies
not instantly kill agents because of minor planning mistakes.

Do not script HOW needs must be satisfied.

Food might be obtained through whatever World Explorer legitimately supports:

mapped commerce
gathering
fishing
hunting
resource transfer
another agent
stored reserves.

Do not force a specific economic system.

============================================================
7. RESOURCES AND OWNERSHIP
============================================================

Agents must have physically/logically bounded resources.

Track:

personal inventory
home storage if available
shared storage if created
resource transfers
resource consumption
resource acquisition
resource loss.

Do not create unlimited resources solely to keep the experiment alive.

Likewise, do not manufacture artificial scarcity merely to force conflict.

Experimental scarcity must be an explicit treatment.

============================================================
8. HOMES
============================================================

Allow agents to establish persistent homes using the existing World Explorer
building/interior/property architecture.

Do not assign every agent a house unless the experimental condition requires it.

Agents may:

choose shelter
return repeatedly
store things where supported
invite others where access permits
move
share space
remain without a stable home.

Observe what happens.

Home location must have actual spatial consequences.

============================================================
10. NO HIDDEN CHAIN OF THOUGHT
============================================================

Do not attempt to expose model chain-of-thought.

Record concise structured decision summaries such as:

CURRENT GOAL
OBSERVED PROBLEM
AVAILABLE OPTIONS
SELECTED ACTION
CONFIDENCE
REASON CATEGORY
EXPECTED RESULT.

Example:

Goal:
Obtain water.

Observation:
Nearby store purchase failed twice.

Classification:
Possible software defect.

Chosen action:
Ask nearby agent whether store worked previously.

Reason:
Need additional evidence before engineering escalation.

This gives observable reasoning evidence without hidden internal reasoning.

============================================================
15. RULES AND INSTITUTIONS
============================================================

Do NOT start with a government.

Provide only the ability to:

communicate
remember
create supported shared artifacts
make commitments
accept/refuse proposals.

If agents begin establishing persistent shared rules or procedures, record them.

A candidate institution requires more than one conversation.

Define an observational criterion such as:

a persistent shared rule/process
recognized by multiple agents
affecting behavior across multiple interactions
persisting beyond the original proposal.

Do not automatically enforce agent-created rules in code.

If agents want software enforcement, that becomes a capability proposal and must
pass the engineering process.

============================================================
16. CONFLICT
============================================================

Do not deliberately create violence as the default experimental driver.

Use existing safe World Explorer interaction systems.

Conflict may include:

resource disagreement
access disagreement
failed commitments
competing goals
information disagreement.

If existing defensive/combat gameplay is enabled in an experimental condition,
record it separately.

Do not make conflict necessary for societal emergence.

============================================================
17. DEATH / FAILURE / RECOVERY
============================================================

Define experimentally what happens when an agent cannot maintain its needs.

For early runs, prefer:

incapacitation
recovery
experiment failure state

over permanently deleting valuable agent history.

Later experiments may include irreversible agent loss if scientifically useful.

All conditions must be explicit.

============================================================
20. SOFTWARE-ENVIRONMENT DISTINCTION
============================================================

Agents must first attempt to solve problems THROUGH THE WORLD.

Engineering intervention is exceptional.

Failure classification:

NORMAL_OBSTACLE
BAD_PLAN
RESOURCE_SHORTAGE
MISSING_DATA
UNSUPPORTED_FEATURE
POSSIBLE_SOFTWARE_DEFECT
SOFTWARE_DEFECT
CAPABILITY_GAP.

Example:

No nearby mapped store
→ missing environmental/data availability.

Do not edit source.

Purchase throws server exception
→ possible software defect.

Repeated need for shared storage where no mechanism exists
→ possible capability gap.

============================================================
21. SOFTWARE KNOWLEDGE IS NOT UNIVERSAL
============================================================

Do not automatically make every resident an expert programmer.

All agents may potentially request diagnostic access under the experiment rules,
but technical competence should be based on:

agent configuration
experience
learned repair memory
shared technical knowledge.

Track whether technical specialization emerges.

============================================================
22. ENGINEERING ESCALATION
============================================================

Use the isolated engineering system from the embodied-maintainer experiment.

An agent may:

collect evidence
discuss problem

create isolated worktree
run tests

It may not:

modify production
modify experiment evaluator
modify benchmark definitions

============================================================
23. COLLECTIVE SOFTWARE PROBLEM SOLVING
============================================================

Allow agents to communicate about technical problems.

Example:

Agent A encounters store failure.
Agent B encountered same failure yesterday.
Agent C has previous technical experience.

They may collectively conclude that investigation is justified.

Record:

who first observed problem
who communicated it
how information spread
who diagnosed it
who proposed repair
who tested it
who benefited afterward.

Do not assign these roles.

============================================================
24. CAPABILITY CREATION
============================================================

Require evidence of a recurring unsatisfied goal.

A capability proposal must contain:

why existing systems are insufficient
minimal proposed capability

expected benefit
possible risks.

Then use isolated implementation/testing.

28. SOCIETY-LEVEL FITNESS IS NOT THE ONLY GOAL
============================================================

Do not optimize agents directly toward:

For evolutionary comparisons use basic viability and competence measures:

cost.

Then independently observe social outcomes.

Otherwise the experiment would manufacture the behavior it claims to discover.
